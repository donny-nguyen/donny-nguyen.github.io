# Pyenv

**Pyenv** is a powerful tool for managing multiple versions of Python on a single system. It’s especially useful for developers who work on projects that require different Python versions or want to avoid conflicts with the system-installed Python.

### 🧰 What Pyenv Does

- **Version Switching**: Easily switch between Python versions (e.g., 3.12, 3.11, 3.9) for different projects.
- **Local vs Global Versions**: Set a global default Python version or override it per project using `.python-version` files.
- **Installation Management**: Install multiple Python versions side-by-side without interfering with your system Python.
- **Shell-specific Versions**: Set a Python version for the current shell session only.
- **Plugin Support**: Extend functionality with plugins like `pyenv-virtualenv` for managing virtual environments.

### ⚙️ How It Works

Pyenv works by inserting a directory of **shims** at the front of your `PATH`. A shim is a lightweight executable that intercepts the `python`, `pip`, and related commands. When you run one of these commands, pyenv:

1. Intercepts the command through the shim.
2. Determines which Python version to use by checking, in order:
   - The `PYENV_VERSION` environment variable.
   - The application-specific `.python-version` file in the current directory (and parent directories).
   - The global `$(pyenv root)/version` file.
3. Passes the command along to the correct Python installation.

Because pyenv operates purely at the shell level, it never modifies your system Python and requires no `sudo` for managing versions.

### 📦 Installation

**macOS (Homebrew):**

```bash
brew update
brew install pyenv
```

**Linux / macOS (automatic installer):**

```bash
curl -fsSL https://pyenv.run | bash
```

The `pyenv.run` installer also sets up useful plugins such as `pyenv-virtualenv` and `pyenv-update`.

**Build dependencies** (needed to compile Python from source):

On macOS:

```bash
brew install openssl readline sqlite3 xz zlib tcl-tk
```

On Ubuntu/Debian:

```bash
sudo apt update
sudo apt install -y make build-essential libssl-dev zlib1g-dev \
  libbz2-dev libreadline-dev libsqlite3-dev wget curl llvm \
  libncursesw5-dev xz-utils tk-dev libxml2-dev libxmlsec1-dev \
  libffi-dev liblzma-dev
```

### 🔧 Shell Configuration

After installing, add pyenv to your shell so the shims load automatically. For **Zsh** (the default on macOS), add the following to `~/.zshrc`:

```bash
export PYENV_ROOT="$HOME/.pyenv"
[[ -d $PYENV_ROOT/bin ]] && export PATH="$PYENV_ROOT/bin:$PATH"
eval "$(pyenv init - zsh)"
```

For **Bash**, add the same lines to `~/.bashrc` (and `~/.bash_profile`), replacing `zsh` with `bash`. Then restart your shell or run:

```bash
source ~/.zshrc
```

### 🛠️ Common Commands

**List available versions to install:**

```bash
pyenv install --list
```

**Install a specific Python version:**

```bash
pyenv install 3.12.4
```

**List installed versions:**

```bash
pyenv versions
```

**Set the global (default) version:**

```bash
pyenv global 3.12.4
```

**Set a version for the current project (creates a `.python-version` file):**

```bash
pyenv local 3.11.9
```

**Set a version for the current shell session only:**

```bash
pyenv shell 3.9.19
```

**Check the active version and why it was chosen:**

```bash
pyenv version
```

**Uninstall a version:**

```bash
pyenv uninstall 3.9.19
```

**Update pyenv (Homebrew):**

```bash
brew upgrade pyenv
```

### 🌱 Managing Virtual Environments with pyenv-virtualenv

The `pyenv-virtualenv` plugin integrates virtual environment management directly into pyenv.

**Create a virtual environment:**

```bash
pyenv virtualenv 3.12.4 myproject-env
```

**Activate it automatically for a project:**

```bash
pyenv local myproject-env
```

**Activate/deactivate manually:**

```bash
pyenv activate myproject-env
pyenv deactivate
```

**List virtual environments:**

```bash
pyenv virtualenvs
```

### 🛠️ Typical Use Cases

- Testing code across multiple Python versions.
- Avoiding dependency conflicts between projects.
- Keeping your system Python untouched while using newer versions for development.
- Reproducing a specific Python version required by a legacy project.

### 🧩 Troubleshooting Tips

- **`command not found: pyenv`**: Ensure the shell configuration lines were added and the shell was restarted.
- **Build fails during `pyenv install`**: Confirm all build dependencies are installed, especially `openssl`, `readline`, `sqlite3`, and `xz`.
- **Wrong version is active**: Run `pyenv version` to see which file or variable is controlling the selection, then check for a stray `.python-version` file.
- **Shims not updating**: Run `pyenv rehash` after installing packages that add new executables.

### Conclusion

If you're working with Python regularly—especially in backend development—Pyenv is a great way to keep your environment clean and flexible. Combined with `pyenv-virtualenv`, it gives you full control over both Python versions and isolated project dependencies, all without touching your system Python.
